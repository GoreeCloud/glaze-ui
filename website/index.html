Glaze UI 1.3 Stable · 1.4 Form-Factor Candidate

One design language. Four interaction environments.

Glaze UI combines layered surfaces, restrained translucency, expressive geometry, accessible motion, clear hierarchy, and GoreeCloud product identity into one adaptive system for mobile, tablet, desktop, TV, and web software.

Explore form factorsView source

Shared semantics stay stable. Layout, density, reachability, navigation, and focus behavior adapt to the device.

Foundations

Polished depth with practical restraint

Glaze uses a deliberate hierarchy of atmospheric canvases, readable solid content surfaces, raised panels, selective functional glass, and attention-priority overlays. Transparency supports hierarchy; it does not replace readability.

CanvasAtmospheric application background
SolidHigh-readability content
RaisedElevated solid panel
GlazeSelective functional translucency

Expressive

Rounded geometry, controlled color, depth, motion, and responsive feedback create personality without overwhelming content.

Accessible

Visible focus, touch-safe targets, reduced motion, reduced transparency, forced-colors resilience, semantic naming, and solid fallbacks are part of the contract.

Private

Core UI does not require analytics, trackers, remote fonts, or unnecessary browser runtime dependencies.

1.4 candidate

Adapt the experience, not the identity.

The same semantic component can take a different physical form depending on screen size, input method, viewing distance, and user context.

Mobile

Reachable actions, thumb-friendly targets, bottom-aware navigation, compact hierarchy, safe areas, and gesture-conscious motion.

Tablet

Flexible split views, side rails, adaptive panes, richer multitasking, and layouts that work in portrait, landscape, and windowed modes.

Desktop

Information density, keyboard and pointer precision, resizable windows, persistent navigation, hover states, shortcuts, and multi-panel workflows.

TV

Ten-foot readability, directional-focus navigation, oversized targets, strong focus rings, simplified density, and remote-first interaction.

Components

Shared semantics, flexible composition

Buttons, fields, selections, navigation, dialogs, status, cards, and progress components keep their meaning while adapting presentation to the target environment.

Adoption

1.3 remains Stable while 1.4 is validated.

Existing consumers should keep using the 1.3 Stable baseline unless they deliberately adopt and validate 1.4 candidate behavior. Form-factor improvements must be tested in the target application rather than assumed safe because they exist in the design-system repository.
