# Glaze UI V1.7 Signature Microinteractions — Open-Source Research

**Date:** 2026-09-26  
**GoreeCloud process:** Reforge — research, compare, extract requirements, independently redesign, validate, document.  
**Target:** V1.7 v1.2 Section 27 — Signature Microinteractions.

## Sources reviewed

1. **Material Components for Android — Motion**  
   https://github.com/material-components/material-components-android/blob/master/docs/theming/Motion.md  
   Useful finding: motion is exposed through semantic patterns and theme-level easing/duration slots rather than requiring each component to invent raw choreography.

2. **IBM Carbon Design System — Motion**  
   https://carbondesignsystem.com/elements/motion/overview/  
   https://github.com/carbon-design-system/carbon/tree/main/packages/motion  
   Useful finding: ordinary component microinteractions are treated as fast, productive feedback while more expressive motion is reserved for rarer, higher-significance moments. Carbon also centralizes motion primitives in a reusable package.

3. **Microsoft Fluent UI — Design Tokens**  
   https://github.com/microsoft/fluentui/blob/master/docs/architecture/design-tokens.md  
   Useful finding: animation duration/easing belong in semantic design tokens rather than component-local hardcoded values, preserving theme/accessibility consistency.

## Strengths retained as requirements

- Use semantic action intent instead of exposing raw duration/easing/physics controls to product code.
- Keep ordinary microinteractions small, quick, readable, and subordinate to the task.
- Limit the number of simultaneously changing visual properties.
- Separate component feedback from larger navigation/composition transitions.
- Preserve a shared system-level motion vocabulary rather than component-specific one-off animation values.
- Keep accessibility and theme behavior compatible with the semantic token layer.

## Limitations not inherited

- GoreeCloud does not use a productive/expressive binary as the authority for whether an application operation succeeded.
- A motion token or component animation must not manufacture provider-owned success, failure, completion, permission, availability, synchronization, security, privacy, or transfer truth.
- Repetition fatigue is governed explicitly: rapid/repeated actions may suppress travel, scale, and icon motion while preserving visible authoritative state.
- Reduced Motion uses an immediate state-feedback equivalent; understanding an action or result cannot depend on observing animation.
- Performance pressure may remove optional motion without changing the authoritative resulting state.
- No upstream source code, timing values, easing curves, or component implementations are copied into this tranche.

## Independent GoreeCloud design objective

Dev.19 defines a first-party semantic microinteraction contract for fifteen Section 27 actions: Toggle, Select, Favorite, Save, Copy, Pin, Expand, Collapse, Refresh, Retry, Send, Download, Upload, Completion, and Reorder.

The contract distinguishes **intent feedback** from **authoritative result feedback**. Intent may be acknowledged when an authoritative action and control identity are supplied. A result-phase presentation is permitted only when the responsible application/provider supplies an authoritative result. Glaze remains presentation-only and never executes the command or changes authoritative application state.

This research record is engineering provenance, not a license to reproduce another design system's source or visual identity.
