# Glaze UI V1.7 Theme Transition System — Open-Source Research

**Date:** 2026-09-26  
**Process:** Reforge — research, compare, extract requirements, independently redesign, validate, document.  
**Target:** V1.7 v1.2 Section 28 — Theme Transition System.

## Sources reviewed

1. **Material Components for Android — Motion**  
   https://github.com/material-components/material-components-android/blob/master/docs/theming/Motion.md  
   Useful finding: theme-level motion should use semantic transition patterns and shared motion slots instead of component-local arbitrary timing and choreography.

2. **Material Components for Android — Color**  
   https://github.com/material-components/material-components-android/blob/master/docs/theming/Color.md  
   Useful finding: theme colors are organized through semantic roles and tonal surface/accent families, allowing coordinated theme changes without every component inventing raw colors.

3. **Microsoft Fluent UI — Design Tokens**  
   https://github.com/microsoft/fluentui/blob/master/docs/architecture/design-tokens.md  
   Useful finding: color, duration, easing, and other visual values should resolve through design tokens rather than hardcoded component values so theming, dark mode, and accessibility stay coherent.

## Requirements retained

- Coordinate theme changes through semantic color/material roles instead of per-component hardcoded values.
- Use a small set of semantic transition channels rather than exposing raw duration/easing/physics controls.
- Keep theme transitions subordinate to state understanding rather than turning theme application into a full-screen spectacle.
- Preserve accessibility overrides and high-contrast/forced-color authority.
- Keep preview behavior distinct from committed application state.

## Limitations not inherited

- Glaze does not infer that a theme has been applied merely because a visual preview or transition reached its target appearance.
- The responsible Theme Manager/provider remains commit authority. A theme is considered applied only after an authoritative committed result is supplied.
- Reduced Motion uses an immediate theme-state replacement rather than requiring animation to understand the selected theme.
- Reduced Transparency uses a solid material equivalent.
- Performance pressure may remove optional interpolation without changing authoritative theme state.
- No upstream source code, exact timing values, easing curves, transition classes, or visual identity are copied into this tranche.

## Independent GoreeCloud design objective

Dev.20 defines a presentation-only Theme Transition System for the eight Section 28 theme properties: Canvas color, Surface color, Accent families, Material atmosphere, Icon tint, Selection color, Non-semantic decorative color, and Appearance mode.

The contract distinguishes cancellable preview from application. Apply-intent presentation may target a proposed theme, but the system reports the target as applied only after the responsible system supplies an authoritative `committed` result. Failed, cancelled, unchanged, or untrusted results do not create an applied-theme claim.

This research record is engineering provenance, not permission to reproduce another design system's source or identity.
