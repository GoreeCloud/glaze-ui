# Contributing to GLAZE UI

GLAZE UI V1.4 — Optical Intelligence (`1.4.0`) is GoreeCloud's current Official Stable, consumer-eligible shared visual and interaction design system. GLAZE UI V1.4.1 is the planned human-validation and optical-hardening follow-up; it is not Stable, consumer-eligible, or completed merely because its protocol or implementation work exists.

Current Stable work must preserve accessibility, semantic clarity, platform-native behavior, exact-revision evidence, consumer-governance boundaries, GoreeCloud repository/revision-control requirements, and the V1.4 Optical Engine's privacy/security authority boundary. V1.4.1 work must preserve V1.4.0 Stable rollback and release provenance while completing the human/manual/physical-device qualification explicitly deferred from V1.4.0.

Do not change `VERSION`, `registry/lifecycle.json`, Official/Stable entrypoints, consumer eligibility, or downstream conformance as a side effect of ordinary implementation or qualification work. Lifecycle promotion requires a separate governed decision with fresh exact-revision evidence. Human and physical-device gates may be supported by automation, but automation must not impersonate the required review authority.

New follow-up behavior should remain additive and must not silently change the public V1.4 token/component contract. Any proposed capability that would alter Stable semantics, compatibility, accessibility, security/privacy boundaries, platform behavior, or migration requirements needs an explicit governed contract, tests, rendered/native evidence as applicable, rollback considerations, and documentation before promotion.

Downstream applications remain independently responsible for repository-local Glaze UI adoption and product acceptance. A shared Glaze UI Stable release never grants application Stable or production eligibility automatically.

Git history remains the required revision audit trail. Historical release and Candidate records may retain the version language that was accurate when they were published when they are clearly provenance-only; current front-door guidance must always follow `VERSION` and `registry/lifecycle.json`.
