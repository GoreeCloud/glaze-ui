# Contributing to GLAZE UI

GLAZE UI V1.6 (`1.6.0`) is GoreeCloud's current Official, Stable, consumer-eligible shared visual and interaction design system. V1.5.1 is the immediate known-good Stable rollback baseline; earlier releases remain historical provenance.

Current Stable work must preserve accessibility, semantic clarity, platform-native behavior, exact-revision evidence, consumer-governance boundaries, presentation-only authority, and GoreeCloud repository/revision-control requirements. Changes to V1.6 must preserve the accepted 24-lane qualification boundary, final Stable security controls, and source/artifact provenance unless a separately governed later release explicitly supersedes them.

Do not change `VERSION`, `registry/lifecycle.json`, Stable entrypoints, consumer eligibility, or downstream conformance as a side effect of ordinary implementation work. Lifecycle promotion requires a separate governed decision with fresh exact-revision evidence. Human, representative-runtime, physical-device, accessibility, and performance gates may be supported by automation, but automation must not impersonate required review or acceptance authority.

The Stable release source/artifact relationship is exact: source `a7180679ea851389e0f3004515f9a25f420e716d`, tag `v1.6.0`, GitHub Release `392095913`, and the published archive digest recorded in `acceptance/v1.6-stable.json`. Do not rewrite or silently replace accepted release identities or bytes.

New behavior not already part of current V1.6.0 Stable authority must remain in an explicitly governed Development, Candidate, or follow-up namespace until formal promotion and must include applicable contracts, tests, rendered/native evidence, accessibility coverage, migration/rollback considerations, and documentation.

Downstream applications remain independently responsible for repository-local V1.6 conformance and production acceptance. Glaze Stable status does not transfer product acceptance.

Git history remains the required revision audit trail. Historical release and Candidate records may retain original language when explicitly historical. Current front-door guidance must derive lifecycle truth from `VERSION` and `registry/lifecycle.json`.

## Retained V1.6 Release Candidate provenance

`1.6.0-rc.1` is retained as superseded, non-consumer-eligible evidence. Changes that alter its historical evidence, frozen-source bindings, or release provenance must be treated as release-sensitive history changes and independently validated.
