# Glaze UI 2.2 Candidate Acceptance

**Candidate:** 2.2.0-candidate.1  
**Current Stable:** 2.1.0  
**Acceptance scope:** Candidate foundation only  
**Consumer eligible:** No

This record tracks the bounded implemented and validated System Shell + Foundation-component tranche for Glaze UI 2.2. It does not establish Stable promotion and does not permit a downstream application to claim Glaze UI 2.2 conformance.

## Objective Candidate checks

The exact-head Candidate workflow verifies at minimum:

- repository `VERSION` remains exactly `2.1.0`;
- lifecycle `currentStable` remains `2.1.0`;
- lifecycle `activeCandidate` is exactly `2.2.0-candidate.1`;
- the Candidate release is not consumer eligible;
- the 2.2 shared state model and priority remain machine readable;
- documented Deep Dark shell anchors are preserved;
- System Shell surface classes remain Workspace, Application, System Overlay, System Panel, Critical System;
- Critical System does not require backdrop blur;
- the System Glaze budget remains one dominant panel plus one to three small floating Glaze controls under ordinary conditions;
- the bounded System Shell runtime passes executable behavior tests;
- the bounded System Shell rendered reference passes responsive/material/accessibility checks;
- all eight Foundation component contracts satisfy shared and component-specific metrics;
- all eight Foundation component contracts are lifecycle-aligned as Candidate;
- rendered Foundation behavior passes a 15-case matrix covering real control state changes and representative mobile, tablet, desktop, Deep Dark, Reduced Motion, Reduced Transparency, Increased Contrast, Forced Colors, RTL, 200% text, and Touch Assistance conditions;
- visible focus, native checked/value semantics, accessible naming, intrinsic sizing, overflow containment, and effects-free fallbacks remain enforced in the bounded Foundation reference;
- no remote presentation dependency is introduced by the Candidate implementation;
- unimplemented 2.2 capabilities remain Planned rather than being mislabeled Candidate or Stable;
- Glaze Motion remains separately Experimental.

## Non-claims

This Candidate foundation does not establish:

- a complete 2.2 component-library implementation;
- any Structure, Overlay, Signature, or Intelligence tier as Candidate unless separately recorded with implementation and evidence;
- a complete Universal Search implementation;
- a complete Control Center implementation;
- an operating-system shell runtime;
- a compositor or window manager;
- an authentication, notification, privacy, security, or search backend;
- native Linux, Android, iOS, macOS, Windows, TV, wearable, or spatial 2.2 certification;
- downstream application adoption;
- production deployment;
- Stable lifecycle status.

## Promotion rule

The Candidate remains non-Stable until all applicable promotion requirements in `STABILITY.md`, `registry/lifecycle.json`, and `GLAZE_UI_2_2_CANDIDATE.md` are complete on exact final revisions.

If an evidence category is not yet recorded, its status is **Pending**, not inferred from source completeness or design-specification breadth.
