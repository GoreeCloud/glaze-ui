# Glaze UI 2.2 Candidate Acceptance

**Candidate:** 2.2.0-candidate.1  
**Current Stable:** 2.1.0  
**Acceptance scope:** Candidate foundation only  
**Consumer eligible:** No

This record tracks the bounded first implementation tranche for Glaze UI 2.2. It does not establish Stable promotion and does not permit a downstream application to claim Glaze UI 2.2 conformance.

## Implemented foundation

The candidate currently includes:

- `GLAZE_UI_2_2_CANDIDATE.md` — Candidate lifecycle and implementation boundary;
- `tokens/glaze-2.2.candidate.json` — machine-readable core and shell tokens;
- `schemas/system-shell-contract.schema.json` — System Shell contract schema;
- `contracts/system-shell/glaze-system-shell-2.2.json` — bounded System Shell foundation contract;
- `css/glaze-2.2.candidate.css` — web reference implementation for the bounded shell foundation;
- `scripts/validate_glaze_2_2_candidate.py` — fail-closed structural validator;
- `.github/workflows/glaze-2.2-candidate.yml` — exact-head Candidate validation workflow;
- `registry/lifecycle.json` — lifecycle registration with Stable 2.1.0 preserved.

## Objective foundation checks

The first Candidate workflow must verify at minimum:

- repository `VERSION` remains exactly `2.1.0`;
- lifecycle `currentStable` remains `2.1.0`;
- lifecycle `activeCandidate` is exactly `2.2.0-candidate.1`;
- the Candidate release is not consumer eligible;
- the 2.2 state model and priority are machine readable;
- documented Deep Dark shell anchors are preserved;
- System Shell surface classes remain Workspace, Application, System Overlay, System Panel, Critical System;
- Critical System does not require backdrop blur;
- the System Glaze budget remains one dominant panel plus one to three small floating Glaze controls under ordinary conditions;
- accessibility fallback requirements remain present;
- Reduced Motion, Reduced Transparency, Increased Contrast, Forced Colors, keyboard, touch, and pointer semantics are represented in the bounded CSS layer;
- no remote presentation dependency is introduced by the Candidate CSS;
- unimplemented 2.2 capabilities remain Planned rather than being mislabeled Candidate or Stable;
- Glaze Motion remains separately Experimental.
