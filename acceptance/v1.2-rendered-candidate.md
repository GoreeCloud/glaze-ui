# GLAZE UI V1.2 — Frosted Neutral Rendered Candidate Acceptance

**Lifecycle:** Candidate evidence  
**Stable baseline:** GLAZE UI V1.1 / 1.1.0  
**Candidate:** GLAZE UI V1.2 / 1.2.0-candidate  
**Promotion authority:** None. Passing this gate does not promote V1.2 or migrate consumers.

This acceptance record defines the bounded rendered-web gate for the Frosted Neutral Candidate. The source contract validator remains authoritative for machine-readable Candidate structure; this gate proves that the checked-out revision can render the Candidate reference surfaces in a real Chromium-class browser without violating selected material, accessibility, target-size, and responsive invariants.

## Required rendered references

The gate renders the following exact repository references through `css/glaze-v1.2.0-candidate.css`:

- `reference/v1.2/frosted-neutral.html`
- `reference/v1.2/component-gallery.html`
- `reference/v1.2/system-shell.html`

The reference set must remain activated on the V1.1 Stable baseline using `data-glaze-upgrade="v1.2-frosted-neutral"` until a later governed promotion changes lifecycle authority.

## Required evidence matrix

The rendered gate must produce reviewable screenshots for:

- Frosted Neutral material reference — Light.
- 32-component gallery — Light.
- System Shell — Light.
- System Shell — Dark.
- System Shell — Deep Dark.
- System Shell — Reduced Transparency.
- System Shell — Forced Colors.
- System Shell — compact mobile viewport.

Screenshots are workflow artifacts and are evidence for the exact checked-out revision only. They are not permanent Stable baselines unless a later governed process explicitly promotes and source-pins them.

## Required rendered assertions

The browser gate fails closed unless it can demonstrate all of the following:

1. The Candidate entrypoint is loaded and the V1.2 upgrade activation is present.
2. Base, Raised, Overlay, and Panel glass tokens resolve to chromatically neutral rendered substrates.
3. The component gallery contains exactly 32 unique inherited component samples.
4. At least the intended transient/floating component set renders backdrop-dependent Frosted Neutral material while dialogs remain non-backdrop-dependent.
5. The System Shell contains exactly the inherited five regions: `workspace`, `navigation`, `universal-search`, `control-center`, and `critical-system`.
6. Floating navigation, Universal Search chrome, and the Control Center render the intended Glaze/Deep Glaze hierarchy.
7. Search result rows and Control Center local controls do not add nested backdrop blur.
8. Critical System remains high-opacity/non-backdrop-dependent.
9. Interactive shell controls satisfy the inherited 48px target floor and the 56px Touch Assistance floor.
10. Keyboard focus remains visibly outlined.
11. Reduced Transparency removes shell backdrop blur while retaining hierarchy and state.
12. Increased Contrast strengthens visible boundaries before adding chroma.
13. 200% text causes Control Center to reflow without root horizontal overflow or target shrinkage.
14. Forced Colors removes custom shell glass/shadows and defers to platform colors.
15. The compact mobile reference does not introduce root horizontal overflow.

## Boundary

Passing `scripts/validate_glaze_v1_2_rendered.py` establishes **bounded rendered web Candidate evidence only**. It does not establish:

- human optical approval;
- a source-pinned immutable visual regression baseline;
- native Android, Wear OS, iOS, macOS, Windows, Linux toolkit, watchOS, TV, spatial, or physical-device acceptance;
- screen-reader or full assistive-technology certification;
- downstream GoreeCloud application conformance;
- production eligibility;
- Stable promotion.

V1.1 / 1.1.0 remains the current Stable authority until a separately governed V1.2 release process completes all applicable gates.
