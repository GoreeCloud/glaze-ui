## Defects discovered before acceptance

The earlier 1.2 candidate passed source CI but acceptance review identified incomplete increased-contrast/forced-colors coverage for new 1.2 controls. The candidate was corrected before rendered promotion. Textarea, switch, segmented selection, progress, banners, selected/checked states, and focus treatment now participate in the accessibility fallback layer, and the source validator fails closed if that coverage disappears.

## Acceptance infrastructure added

Glaze UI now includes:

- `ACCEPTANCE.md` — canonical Stable-release acceptance protocol;
- `reference/acceptance.html` — browser-render acceptance harness;
- `scripts/validate_rendered_reference.py` — Chromium rendered acceptance runner;
- a permanent CI step that executes the rendered acceptance matrix on pull requests and main pushes.

## Remaining manual boundary

`prefers-reduced-transparency` does not have a reliable cross-runner Chromium command-line emulation contract in this acceptance harness. Its CSS fallback remains source-validated, and representative platform review should still exercise reduced-transparency behavior when the target browser/OS exposes that preference. The Stable release does not claim that unsupported browser media emulation was executed.

## Promotion result

The 1.2 application-interface candidate passed source validation, deterministic public-site validation, and the browser-rendered reference matrix. Release-record changes are presentation-neutral and remain subject to the same permanent CI gate. Glaze UI 1.2.0 is accepted for Stable promotion.
