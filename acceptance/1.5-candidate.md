# Glaze UI 1.5 Candidate Acceptance Record

## Release identity

- Candidate version: `1.5.0-candidate`
- Stable baseline preserved: `1.4.0`
- Development pull request: `#81 — Add Glaze UI 1.5 motion, materials, layout, and state contracts`
- Candidate scope: adaptive color, iconography, motion/interaction, material/depth, layout/spacing/density, and semantic interaction-state/input-modality behavior.
- Wear OS remains outside the 1.5 Candidate acceptance scope.

## Source validation

The Candidate is required to pass the exact-revision Glaze UI CI stack, including adaptive color, iconography, motion, material/depth, layout/spacing/density, interaction states/input modality, typography, enforcement, form-factor, consumer-registry, Firefox integration, public-site, and retained Stable rendered-reference checks.

Passing source validation does not by itself promote 1.5 or authorize production conformance.

## Layout source acceptance

`LAYOUT.md`, `tokens/layout.json`, `css/glaze.layout.css`, and `scripts/validate_layout.py` define and enforce semantic spacing, responsive gutters, bounded content measures, density modes, accessible target floors, safe-area behavior, overflow containment, localization tolerance, semantic/focus-order consistency, and the prohibition on selecting compact density solely from viewport width.

## State and modality source acceptance

`STATES.md`, `tokens/states.json`, `css/glaze.states.css`, and `scripts/validate_states.py` define and enforce:

- default, hover, focus-visible, pressed, selected, expanded, disabled, read-only, loading, invalid, and success state roles;
- keyboard, pointer, touch, remote/gamepad, assistive-technology, and mixed-input modality behavior;
- hover as supplemental rather than a required path;
- visible focus presentation across materials and accessibility/performance fallbacks;
- semantic distinction between pressed, selected, and expanded;
- semantic and visual distinction between disabled and read-only;
- truthful busy/loading state and determinate-progress requirements;
- semantic invalid state with an accessible explanation;
- status communication that does not rely on color alone; and
- application authority over actual availability, selection, busy, validation, and workflow truth.

## Rendered Candidate acceptance

`reference/candidate-1.5.html` is the isolated visual target for 1.5 motion, material, layout, and state evidence. It does not alter the Stable 1.4 reference experience.

`reference/candidate-1.5-acceptance.html` and `scripts/validate_candidate_1_5_rendered.py` fail closed on representative Candidate behavior including:

- Solid, Raised, Functional Glass, Clear Glass, scrim, and Overlay material roles and depth ordering;
- semantic enter/state/progress motion plus reduced-motion substitution;
- responsive gutter floors, bounded standard/prose/form measures, 44px coarse targets, bounded internal horizontal scrolling, and no root horizontal overflow;
- comfortable density across Mobile 390×844, Tablet 820×1180, Desktop 1280×900, and TV 1920×1080, plus explicit compact density on Desktop and spacious density on Mobile;
- rendered focus-visible geometry, persistent selected treatment, expanded disclosure indication, semantic disabled/read-only distinction, truthful `aria-busy`, semantic invalid state with accessible explanation, and explicit success status;
- preservation of focus/state distinction under reduced-motion, reduced-transparency, and constrained-performance cases;
- light and dark appearances across all representative form-factor viewports; and
- portable reduced-transparency and constrained-performance material fallbacks.

## Acceptance boundaries

The rendered suite proves the platform-neutral web reference contract only. It provides representative evidence for motion, materials, layout, density, target geometry, overflow containment, and semantic interaction-state presentation.

These gates do not substitute for consumer-specific native mapping, real-device testing, application accessibility review, product performance testing, physical cutout/overscan validation, production-string localization, native remote/gamepad directional-navigation testing, screen-reader product testing, or downstream migration evidence.

Glaze UI presentation cannot manufacture privacy, security, resilience, coordination, availability, selection, busy, validation, or workflow truth. Privacy Shield, Wardveil Security, Everkeep, GoreeCloud Mesh, and application logic remain authoritative for those underlying states.

## Promotion decision

The Candidate remains unpromoted until the complete exact-head CI stack succeeds and the remaining 1.5 Candidate promotion requirements are reviewed. Glaze UI 1.4.0 remains the current Stable production baseline and consumer target.

## Rollback

Because 1.5 remains isolated Candidate work, rollback is branch/PR-level: close or revert the Candidate changes without altering the 1.4.0 Stable baseline or forcing consumer migration.
