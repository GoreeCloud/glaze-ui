# Glaze UI 1.5 Candidate Acceptance Record

## Release identity

- Candidate version: `1.5.0-candidate`
- Stable baseline preserved: `1.4.0`
- Development pull request: `#81 — Add Glaze UI 1.5 motion, materials, and layout contracts`
- Candidate scope: adaptive color, iconography, motion/interaction, material/depth, and layout/spacing/density semantics.
- Wear OS remains outside the 1.5 Candidate acceptance scope.

## Source validation

The Candidate is required to pass the exact-revision Glaze UI CI stack, including adaptive color, iconography, motion, material/depth, layout/spacing/density, typography, enforcement, form-factor, consumer-registry, Firefox integration, public-site, and retained Stable rendered-reference checks.

Passing source validation does not by itself promote 1.5 or authorize production conformance.

## Layout source acceptance

`LAYOUT.md`, `tokens/layout.json`, `css/glaze.layout.css`, and `scripts/validate_layout.py` define and enforce the Candidate spatial architecture. The source gate requires:

- the canonical semantic spacing scale and role mappings;
- responsive compact, medium, expanded, and large-screen gutters;
- bounded prose, form, standard, and wide content measures;
- comfortable, compact, and spacious density modes;
- preservation of interactive-target minimums across density modes;
- safe-area-aware page primitives;
- a root horizontal-overflow prohibition with bounded internal scrolling for intrinsically wide content;
- localization, text-expansion, semantic-order, and focus-order requirements;
- prohibition on choosing compact density solely from viewport width; and
- preservation of the Glaze UI presentation authority boundary.

## Rendered Candidate acceptance

`reference/candidate-1.5.html` is the isolated visual target for 1.5 motion, material, and layout evidence. It does not alter the Stable 1.4 reference experience.

`reference/candidate-1.5-acceptance.html` and `scripts/validate_candidate_1_5_rendered.py` fail closed on representative Candidate behavior including:

- Canvas-adjacent Solid and Raised content surfaces;
- Functional Glass with bounded backdrop treatment;
- Clear Glass over visually rich media;
- scrim/Overlay depth ordering;
- semantic enter, state, press/focus, and determinate-progress motion roles;
- responsive page-gutter floors at compact, medium, expanded, and large-screen representative widths;
- bounded standard, prose, and form content measures;
- a minimum 44px coarse interactive-target floor;
- bounded internal horizontal scrolling for intrinsically wide content without root viewport overflow;
- comfortable density across the representative form-factor matrix;
- explicit compact density at Desktop 1280×900 and explicit spacious density at Mobile 390×844, proving density is not inferred solely from viewport width;
- rendered density multipliers and semantic spacing-gap changes while target geometry remains accessible;
- light and dark appearances at Mobile 390×844, Tablet 820×1180, Desktop 1280×900, and TV 1920×1080 representative viewports;
- reduced-motion substitution with animation and transition travel removed;
- portable reduced-transparency behavior using the explicit Glaze UI web adapter;
- reduced-transparency behavior independently from reduced motion;
- constrained-performance fallback that removes backdrop filtering without removing hierarchy or information; and
- absence of root horizontal overflow across the representative matrix.

## Acceptance boundaries

The rendered suite proves the platform-neutral web reference contract only. It now provides representative rendered evidence for motion, materials, layout, responsive gutters, measures, density selection, target geometry, and overflow containment.

These gates do not substitute for consumer-specific native mapping, real-device testing, application accessibility review, product performance testing, safe-area behavior on physical cutout/overscan hardware, localization review with production strings, or downstream migration evidence.

Material appearance or spatial presentation cannot manufacture privacy, security, resilience, or coordination truth. Privacy Shield, Wardveil Security, Everkeep, and GoreeCloud Mesh remain authoritative for those underlying states; Glaze UI remains authoritative for their presentation contract.

## Promotion decision

The Candidate remains unpromoted until the complete exact-head CI stack succeeds and the remaining 1.5 Candidate promotion requirements are reviewed. Glaze UI 1.4.0 remains the current Stable production baseline and current consumer target.

## Rollback

Because 1.5 remains isolated Candidate work, rollback is branch/PR-level: close or revert the Candidate changes without altering the 1.4.0 Stable baseline or forcing consumer migration.
