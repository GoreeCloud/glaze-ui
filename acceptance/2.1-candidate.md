# Glaze UI 2.1 Candidate Acceptance — Reference Flow, Resilience and Source-Pinned Visual Regression

Status: **Candidate evidence only**. Current Stable remains **2.0.0**.

This acceptance record defines the current rendered/reference-flow, resilience, interaction and screenshot pixel-regression slice for Glaze UI 2.1. It does not represent Stable promotion and does not claim complete 2.1 platform, native-device, downstream-consumer, compatibility/migration, or human Visual Excellence acceptance.

## Implemented canonical reference flows

1. **Settings / Preferences** — appearance, Material Clarity, expression, accessibility resolution, protected platform-state presentation, adaptive navigation, reachability and restrained material use.
2. **File Management** — solid file content, adaptive navigation, search/action chrome, Live Glaze activity, and explicit local/cloud/sync/backup/conflict vocabulary.
3. **Search / Command** — search as navigation state, bounded command expansion, focus return, state completeness, and content-first result presentation.
4. **Communication / Live Activity** — readable conversation content, message delivery transitions, verified/protected state, live activity, composer behavior, and the Communication Material Budget.
5. **Media Playback** — media-first composition, bounded expressive controls, playback continuity, Live Glaze activity, far-view/TV targets, and the Media Material Budget.
6. **Resilience / Exceptional States** — empty, unavailable, conflict, expired, destructive, degraded, offline, protected and restricted presentation with explicit recovery actions and a clear statement that the page does not assert live GoreeCloud platform status.

## Expanded representative matrix

The Candidate matrix covers mobile, tablet, desktop, wide desktop and TV/far-view rendering; Light, Dark and Deep Dark; Clear, Balanced and Solid material behavior; Full, Balanced, Constrained and Minimal performance behavior; 200% Large Text; Touch Assistance; Reduced Transparency; Reduced Motion; Increased Contrast; platform Forced Colors; three explicit interaction-continuity scenarios; and resilience/exceptional-state presentation.

The explicit interaction scenarios remain:

- **command-open-select** — command surface opens from a stable source, remains within the Productivity Material Budget, selection completes, and focus returns to the source.
- **message-send** — a draft becomes a sent message without losing conversation position, action focus or explicit delivery state.
- **playback-toggle** — playback changes from paused to playing while control identity, media position context and Live Activity presentation remain continuous.

## State-completeness evidence

The reference set exercises default, selected, disabled, loading, sending, success, warning, error, offline, protected, restricted, empty, unavailable, conflict, expired, destructive and degraded persistent states. Hover, focus and pressed behavior are represented through explicit CSS interaction selectors and rendered interaction controls. State meaning is labeled and does not depend on color alone.

## Runtime Material Budget evidence

Reference pages measure simultaneously visible `glaze`, `deep-glaze` and `live-glaze` viewport area after layout and after tested interaction transitions.

- Productivity: maximum 22% high-intensity viewport area.
- Communication: maximum 30%.
- Media: maximum 45%.
- Administration: maximum 16%, used by the Resilience / Exceptional States reference.

The existing count limits for Deep Glaze and Live Glaze remain enforced by the shared runtime. Offscreen or fully hidden material does not consume visible area in the reference harness.

Those images were inspected for gross clipping and incorrect snapshot-state errors before the baseline revision was pinned. That inspection is provenance review only and **is not recorded human Visual Excellence acceptance**.

Normal Candidate CI now checks out both the current exact source and the immutable baseline source revision. It renders the same six manifest cases for the baseline source and the current source on the same Ubuntu/Chromium runner, then executes `scripts/glaze_2_1_visual_regression.py compare` against the separately rendered baseline directory. The compare command fails closed if an external baseline directory is not supplied, so the current render cannot silently bless itself.

This source-pinned/same-run strategy provides two useful controls:

1. **Immutable design reference** — a source change cannot modify the baseline without an explicit baseline-revision update.
2. **Browser-cohort consistency** — baseline and candidate pixels are rendered by the same runner/browser cohort, reducing false diffs caused solely by a Chromium upgrade between historical and current CI runs.

The source-pinned baseline does not claim permanent archival of every historical rendered PNG. The original exact capture artifact and hashes remain provenance for the baseline decision; longer-lived rendered-baseline preservation may be hardened separately without changing the Candidate design reference.

## Pixel thresholds

The six-case comparator retains the manifest thresholds established during staging:

- per-channel tolerance: `12`
- maximum changed-pixel ratio: `0.75%`
- maximum mean absolute channel delta: `1.5`

The PNG decoder/comparator uses the Python standard library and writes a diagnostic diff image when a case exceeds the thresholds.

## Visual regression boundary

Computed rendered visual-invariant regression, interaction regression, resilience-state rendering and the source-pinned six-case screenshot pixel regression are Candidate evidence. Human Visual Excellence review remains a distinct perceptual-quality gate and may still block Stable promotion even when every automated visual comparison passes.

An intentional visual redesign that exceeds the screenshot thresholds requires an explicit baseline refresh process: review a new exact-head capture, pin the new source revision and provenance, and obtain fresh exact-head comparison evidence. CI must not automatically repin the baseline to the changed source.

## Promotion boundary

This evidence proves only that the specified web reference flows, runtime contracts, computed visual invariants, interaction scenarios, resilience states and source-pinned screenshot cases satisfy their applicable objective Candidate checks at an exact tested revision.

Stable promotion still requires native/runtime mappings where applicable, representative physical-device evidence, compatibility/migration review, downstream consumer evidence, exact-final-revision promotion acceptance, and recorded human Visual Excellence acceptance. Glaze UI 2.0.0 remains the only current Stable consumer target until those gates are satisfied.
