# Glaze UI 2.1 Candidate Acceptance — Reference Flow and Regression Foundation

Status: **Candidate evidence only**. Current Stable remains **2.0.0**.

This acceptance record defines the current rendered/reference-flow and regression evidence slice for Glaze UI 2.1. It does not represent Stable promotion and does not claim complete 2.1 platform, native-device, downstream-consumer, pixel-baseline, or human Visual Excellence acceptance.

## Implemented canonical reference flows

1. **Settings / Preferences** — appearance, Material Clarity, expression, accessibility resolution, protected platform-state presentation, adaptive navigation, reachability and restrained material use.
2. **File Management** — solid file content, adaptive navigation, search/action chrome, Live Glaze activity, and explicit local/cloud/sync/backup/conflict vocabulary.
3. **Search / Command** — search as navigation state, bounded command expansion, focus return, state completeness, and content-first result presentation.
4. **Communication / Live Activity** — readable conversation content, message delivery transitions, verified/protected state, live activity, composer behavior, and the Communication Material Budget.
5. **Media Playback** — media-first composition, bounded expressive controls, playback continuity, Live Glaze activity, far-view/TV targets, and the Media Material Budget.

## Executable runtime evidence

- `js/glaze-2.1.candidate.mjs` applies the Candidate preference-resolution order and deterministic material/performance policy used by the reference pages.
- `tests/glaze-2.1-runtime.test.mjs` validates Reduced Transparency, Forced Colors, Reduced Motion, 200% Large Text with Compact density, Touch Assistance, performance degradation and Material Budget pass/fail behavior.
- `reference/candidate-2.1-settings.html` and `reference/candidate-2.1-files.html` retain the first bounded reference-flow slice.
- `reference/candidate-2.1-search.html`, `reference/candidate-2.1-communication.html`, and `reference/candidate-2.1-media.html` extend the canonical flow set across search/command, communication/live activity and media playback.
- `reference/candidate-2.1-acceptance.html` plus `scripts/validate_glaze_2_1_rendered.py` retain the first rendered flow matrix.
- `contracts/regression/reference-invariants.json`, `reference/candidate-2.1-expanded-acceptance.html`, `scripts/validate_glaze_2_1_regression.py`, and `scripts/validate_glaze_2_1_expanded_rendered.py` define and execute the expanded computed visual-invariant and interaction-regression slice.

## Expanded representative matrix

The Candidate matrix now covers mobile, tablet, desktop, wide desktop and TV/far-view rendering; Light, Dark and Deep Dark; Clear, Balanced and Solid material behavior; Full, Balanced, Constrained and Minimal performance behavior; 200% Large Text; Touch Assistance; Reduced Transparency; Reduced Motion; Increased Contrast; platform Forced Colors; and three explicit interaction-continuity scenarios.

The first explicit interaction scenarios are:

- **command-open-select** — command surface opens from a stable source, remains within the Productivity Material Budget, selection completes, and focus returns to the source.
- **message-send** — a draft becomes a sent message without losing conversation position, action focus or explicit delivery state.
- **playback-toggle** — playback changes from paused to playing while control identity, media position context and Live Activity presentation remain continuous.

## State-completeness evidence

The expanded reference set exercises default, selected, disabled, loading, sending, success, warning, error, offline, protected and restricted persistent states. Hover, focus and pressed behavior are represented through explicit CSS interaction selectors and rendered interaction controls. State meaning is labeled and does not depend on color alone.

## Runtime Material Budget evidence

Reference pages measure simultaneously visible `glaze`, `deep-glaze` and `live-glaze` viewport area after layout and after the tested interaction transitions.

- Productivity: maximum 22% high-intensity viewport area.
- Communication: maximum 30%.
- Media: maximum 45%.

The existing count limits for Deep Glaze and Live Glaze remain enforced by the shared runtime. Offscreen or fully hidden material does not consume visible area in the reference harness.

## Visual regression boundary

The current Candidate regression is **computed visual-invariant regression**, not pixel screenshot diffing. It checks solid content planes, material/fallback behavior, visual state markers, target floors, selected-navigation treatment, no horizontal overflow, Deep Dark canvas behavior, accessibility modes, form-factor navigation and Material Budgets.

Pixel/screenshot baseline capture and image-diff regression remain **Planned** and are not claimed by this evidence.

## Promotion boundary

This evidence proves only that the specified web reference flows, runtime contracts, computed visual invariants and interaction scenarios satisfy their objective Candidate checks at an exact tested revision.

Stable promotion still requires pixel/screenshot visual-regression evidence, broader canonical flows and uncommon-state coverage, native/runtime mappings where applicable, representative physical-device evidence, compatibility/migration review, downstream consumer evidence, exact-final-revision acceptance, and recorded human Visual Excellence acceptance.
