# Glaze UI 2.1 Candidate Acceptance — Reference Flow, Resilience, Visual Regression and Native Android

Status: **Candidate evidence only**. Current Stable remains **2.0.0**.

This acceptance record defines the current rendered/reference-flow, resilience, interaction, screenshot pixel-regression, bounded Android-native and consumer-assessment slices for Glaze UI 2.1. It does not represent Stable promotion and does not claim complete 2.1 platform, physical-device, downstream-consumer, screen-reader, production-signing, or human Visual Excellence acceptance.

## Implemented canonical reference flows

1. **Settings / Preferences** — appearance, Material Clarity, expression, accessibility resolution, protected platform-state presentation, adaptive navigation, reachability and restrained material use.
2. **File Management** — solid file content, adaptive navigation, search/action chrome, Live Glaze activity, and explicit local/cloud/sync/backup/conflict vocabulary.
3. **Search / Command** — search as navigation state, bounded command expansion, focus return, state completeness, and content-first result presentation.
4. **Communication / Live Activity** — readable conversation content, message delivery transitions, verified/protected state, live activity, composer behavior, and the Communication Material Budget.
5. **Media Playback** — media-first composition, bounded expressive controls, playback continuity, Live Glaze activity, far-view/TV targets, and the Media Material Budget.
6. **Resilience / Exceptional States** — empty, unavailable, conflict, expired, destructive, degraded, offline, protected and restricted presentation with explicit recovery actions and a clear statement that the page does not assert live GoreeCloud platform status.

## Expanded representative matrix

The Candidate web matrix covers mobile, tablet, desktop, wide desktop and TV/far-view rendering; Light, Dark and Deep Dark; Clear, Balanced and Solid material behavior; Full, Balanced, Constrained and Minimal performance behavior; 200% Large Text; Touch Assistance; Reduced Transparency; Reduced Motion; Increased Contrast; platform Forced Colors; three explicit interaction-continuity scenarios; and resilience/exceptional-state presentation.

The explicit interaction scenarios remain:

- **command-open-select** — command surface opens from a stable source, remains within the Productivity Material Budget, selection completes, and focus returns to the source.
- **message-send** — a draft becomes a sent message without losing conversation position, action focus or explicit delivery state.
- **playback-toggle** — playback changes from paused to playing while control identity, media position context and Live Activity presentation remain continuous.

## State-completeness evidence

The reference set exercises default, selected, disabled, loading, sending, success, warning, error, offline, protected, restricted, empty, unavailable, conflict, expired, destructive and degraded persistent states. Hover, focus and pressed behavior are represented through explicit CSS interaction selectors and rendered interaction controls. State meaning is labeled and does not depend on color alone.

## Runtime Material Budget evidence

Reference pages measure simultaneously visible `glaze`, `deep-glaze` and `live-glaze` viewport area after layout and after tested interaction transitions.

- Productivity: maximum 22% high-intensity viewport area.
- Communication: maximum 30%.
- Media: maximum 45%.
- Administration: maximum 16%, used by the Resilience / Exceptional States reference.

The existing count limits for Deep Glaze and Live Glaze remain enforced by the shared runtime. Offscreen or fully hidden material does not consume visible area in the reference harness.

Normal Candidate CI checks out both the current exact source and the immutable baseline source revision. It renders the same six manifest cases for the baseline source and the current source on the same Ubuntu/Chromium runner, then executes `scripts/glaze_2_1_visual_regression.py compare` against the separately rendered baseline directory. The compare command fails closed if an external baseline directory is not supplied, so the current render cannot silently bless itself.

This source-pinned/same-run strategy provides two useful controls:

1. **Immutable design reference** — a source change cannot modify the baseline without an explicit baseline-revision update.
2. **Browser-cohort consistency** — baseline and candidate pixels are rendered by the same runner/browser cohort, reducing false diffs caused solely by a Chromium upgrade between historical and current CI runs.

## Pixel thresholds

The six-case comparator retains the original staged thresholds without relaxation:

- per-channel tolerance: `12`
- maximum changed-pixel ratio: `0.75%`
- maximum mean absolute channel delta: `1.5`

The PNG decoder/comparator uses the Python standard library and writes a diagnostic diff image when a case exceeds the thresholds.

## Native Android handheld Candidate slice

`reference/native/android/buildable/` is a minimal original Android application that maps Glaze UI 2.1 semantics onto Android framework controls. It does not embed the web reference and does not request network access.

The source contract includes solid Canvas/Surface content, a bounded Glaze action zone, 48 dp general and 56 dp Touch Assistance target floors, Light/Dark/Deep Dark mappings, true-black Deep Dark canvas, Reduced Transparency resolving to a Solid interaction treatment, native `sp` text scaling inside a reflowing scroll container, text-labeled simulated Protected/Offline/Conflict states, and an explicit native action-state transition.

The Android 16 reference now applies system-bar insets to the scroll viewport so 200% Large Text does not travel under the status bar, and the Glaze actions use deterministic non-elevated framework button treatment rather than inheriting a raised default appearance.

`.github/workflows/glaze-2.1-android-native.yml` is the authoritative exact-source native gate. It validates the native structure, resolves a stable hosted Android `google_apis` x86_64 image, installs a verified Gradle 9.5.0 distribution, builds the debug APK against compileSdk/targetSdk 36, boots a disposable emulator, installs the APK and executes `scripts/validate_glaze_2_1_android_runtime.py`.

The runtime validator checks three bounded cases: Light/Balanced plus action completion and 48 dp target inspection; Deep Dark plus Reduced Transparency/Solid and true-black markers; and 200% system font scale plus Touch Assistance with a 56 dp target floor. It writes screenshots and `android-native-evidence.json` when successful and binds `sourceRevision` to the actual checked-out Git `HEAD` rather than GitHub's synthetic pull-request merge SHA.

At exact head `b010531f499b701f25f380eb7004291d3cc5f72a`, Glaze UI 2.1 Android Native Candidate workflow run `33319861564` completed successfully. Its artifact `9734610399`, digest `sha256:bbbb70fd3cb5bf0e77628c92d8490e88e0cadbd28c5afa779f45167265ea0f9f`, contains the corrected native screenshots and evidence JSON for that exact source revision.

A green exact-head Android workflow establishes native Android emulator implementation/runtime evidence for this bounded reference only. It does **not** establish TalkBack, Switch Access, OEM/physical-device rendering, Moto G 2026 acceptance, production signing/distribution, battery/performance, interruption restoration, or human Visual Excellence acceptance.

## Consumer Candidate assessment infrastructure

The existing canonical `consumers/registry.json` remains the single Stable consumer audit and uses schema version 4 with `schemas/consumer-registry.schema.json`. Its current Stable target and existing consumer states remain 2.0.0 authority.

A bounded `candidateAssessment` layer targets `2.1.0-candidate.1`, is explicitly `consumerEligible: false` and `productionEligible: false`, and defines fail-closed evidence requirements for future repository-local Candidate evaluations. Candidate evaluations cannot rewrite a consumer's Stable state or satisfy the production gate.

The Candidate evaluation list is intentionally empty at implementation time. Therefore this record claims **no downstream Glaze UI 2.1 adoption or conformance evidence**. `scripts/validate_consumer_registry.py` validates both the unchanged Stable audit and the Candidate assessment boundary.

## Compatibility, migration and rollback

`MIGRATION_2_0_TO_2_1.md` documents the controlled migration from the current 2.0.0 Stable contract to the 2.1 Candidate line. The migration preserves semantic hierarchy and producer-authoritative state, requires explicit adoption of new 2.1 contracts rather than silent opt-in, keeps Candidate behavior from satisfying current Stable consumer conformance, and defines rollback to the 2.0.0 entrypoints while 2.1 remains unpromoted.

This compatibility/migration documentation is implementation evidence, not proof that every downstream GoreeCloud consumer has completed a 2.1 migration. Actual consumer adoption remains separately evidenced in the canonical consumer registry after Stable promotion.

## Visual regression and native evidence boundary

Computed rendered visual-invariant regression, interaction regression, resilience-state rendering and the source-pinned six-case screenshot pixel regression are Candidate web evidence. The Android gate adds bounded native emulator evidence. Human Visual Excellence review remains a distinct perceptual-quality gate and may still block Stable promotion even when every automated comparison and emulator case passes.

An intentional visual redesign that exceeds screenshot thresholds requires an explicit baseline refresh process: review a new exact-head capture, pin the new source revision and provenance, and obtain fresh exact-head comparison evidence. CI must not automatically repin the baseline to the changed source.

## Promotion boundary

This evidence proves only the objective Candidate checks actually exercised by the exact tested revision. Stable promotion still requires representative physical-device/native evidence where emulator/source evidence is insufficient, screen-reader and applicable input/accessibility acceptance where claimed, actual downstream consumer evidence where required by release governance, exact-final-revision promotion acceptance, and recorded human Visual Excellence acceptance.

Glaze UI 2.0.0 remains the only current Stable consumer target until those gates are satisfied.
