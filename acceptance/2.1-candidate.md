# Glaze UI 2.1 Candidate Acceptance — Reference Flow Foundation

Status: **Candidate evidence only**. Current Stable remains **2.0.0**.

This acceptance record defines the first rendered/reference-flow evidence slice for Glaze UI 2.1. It does not represent Stable promotion and does not claim complete 2.1 platform, native-device, consumer-adoption, or human Visual Excellence acceptance.

## Implemented reference flows

1. **Settings / Preferences** — appearance, Material Clarity, expression, accessibility resolution, protected platform-state presentation, adaptive navigation, reachability and restrained material use.
2. **File Management** — solid file content, adaptive navigation, search/action chrome, Live Glaze activity, and explicit local/cloud/sync/backup/conflict vocabulary.

## Executable evidence

- `js/glaze-2.1.candidate.mjs` applies the Candidate preference-resolution order and deterministic material/performance policy used by the reference pages.
- `tests/glaze-2.1-runtime.test.mjs` validates Reduced Transparency, Forced Colors, Reduced Motion, 200% Large Text with Compact density, Touch Assistance, performance degradation and Material Budget pass/fail behavior.
- `reference/candidate-2.1-settings.html` and `reference/candidate-2.1-files.html` are canonical Candidate flows.
- `reference/candidate-2.1-acceptance.html` inspects actual rendered layout, target floors, material fallbacks, accessibility resolution, form-factor navigation, data-location vocabulary and runtime Material Budget results.
- `scripts/validate_glaze_2_1_rendered.py` executes the representative browser matrix.

## Representative matrix

The bounded Candidate matrix covers mobile, tablet, desktop and wide desktop; Light, Dark and Deep Dark; Clear, Balanced and Solid material behavior; Full, Balanced, Constrained and Minimal performance behavior; 200% Large Text; Touch Assistance; Reduced Transparency; Reduced Motion; Increased Contrast; and platform Forced Colors.

## Runtime Material Budget evidence

Reference pages measure simultaneously visible `glaze`, `deep-glaze` and `live-glaze` viewport area after layout. The Productivity recipe is accepted only at or below 22% high-intensity area, no more than two Deep Glaze surfaces and no more than one Live Glaze surface. Offscreen material does not consume visible area in this harness.

## Promotion boundary

This evidence proves only that the specified web reference flows and pure resolver tests satisfy their objective Candidate checks at an exact tested revision. Stable promotion still requires broader canonical flows, expanded interaction/visual regression, runtime/native mappings where applicable, representative physical-device evidence, compatibility/migration review, downstream consumer evidence, and recorded human Visual Excellence acceptance.
