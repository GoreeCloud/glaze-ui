# GLAZE UI V1.1 Specification Candidate Acceptance

Candidate: `1.1.0-candidate.1`  
Lifecycle: **Specification-Stable Candidate**  
Current official target: **GLAZE UI V1.0 / 1.0.0**

This record tracks the acceptance boundary for the V1.1 optical-refinement candidate. It is intentionally separate from release and production acceptance.

## Specification-stability gates

- [x] V1.1 authority and resolution order are explicit.
- [x] V1.1 scope is frozen and exclusions are explicit.
- [x] Deep Teal + Soft Amber atmospheric primitives are fixed.
- [x] Aura and material-tint contributions have deterministic caps.
- [x] Environmental Color Memory is optional, bounded, local by default, non-semantic, and has a no-sampling fallback.
- [x] V1 structural material limits are inherited rather than weakened.
- [x] V1 semantic and protected-state boundaries are inherited rather than redefined.
- [x] V1 accessibility precedence resolves before V1.1 expression.
- [x] A repository validator exists for the candidate contracts.
- [x] A candidate-only CI workflow exists for exact-head validation.

## Implementation and release gates

The following remain required before V1.1 may become the official current target:

- [ ] Exact pull-request head passes the V1.1 candidate validator and applicable existing V1 validators.
- [ ] V1.1 CSS/JS/native presentation entrypoints implement the candidate contracts.
- [ ] Desktop workspace reference scene is rendered and reviewed.
- [ ] Mobile application reference scene is rendered and reviewed.
- [ ] Tablet dashboard reference scene is rendered and reviewed.
- [ ] Light, Dark, and Deep Dark appearance coverage is accepted.
- [ ] Forced Colors coverage is accepted.
- [ ] Reduced Transparency coverage is accepted.
- [ ] Reduced Motion coverage is accepted.
- [ ] Increased Contrast and visible-boundary coverage is accepted.
- [ ] 200% text and large-text reflow coverage is accepted.
- [ ] RTL, keyboard/focus, touch, pointer, and applicable assistive-input coverage is accepted.
- [ ] Material/performance evidence confirms the governed Glaze-region budget and no default nested backdrop stack.
- [ ] Visual-regression baselines exist for representative V1.1 scenes and accessibility variants.
- [ ] Human optical review accepts hierarchy, typography, spacing, curvature, alignment, atmospheric restraint, and state clarity.
- [ ] Platform-native claims have exact-revision platform-native evidence.
- [ ] Repository documentation and GoreeCloud canonical documentation are synchronized to the accepted implementation.
- [ ] A separate governed release decision explicitly promotes V1.1.
- [ ] Lifecycle and current-target records are changed only as part of that governed promotion.

## Release boundary

Passing the checked specification-stability gates means the V1.1 design contract is sufficiently deterministic to implement consistently. It does not establish a Stable release, Production Stable implementation, downstream application conformance, or production acceptance.
