## Implemented Candidate foundation

- normative contract in `GLAZE_UI_2.md`;

- Glaze Material levels Canvas / Surface / Soft Glaze / Glaze / Deep Glaze / Live Glaze;
- new radius, spacing, typography, material, motion, personalization, adaptive-layout, component-family, and accessibility semantics;
- web primitives in `css/glaze-2.candidate.css`;
- clarity modes Clear / Balanced / Solid;
- appearance modes Light / Dark / Deep Dark;
- expression modes Calm / Balanced / Expressive;
- Live Glaze pointer/focus response;
- Navigation Capsule scroll-state behavior;
- Connected Transformation API with native View Transition use where available and state-preserving fallback;
- reduced-transparency, reduced-motion, increased-contrast, forced-colors, and no-backdrop fallbacks;
- fail-closed source validation in `scripts/validate_glaze_2_candidate.py`;
- exact-revision CI integration.

## Accepted Candidate evidence

Rendered acceptance is implemented by `reference/candidate-2.0.html`, `reference/candidate-2.0-acceptance.html`, and `scripts/validate_candidate_2_rendered.py`. Exact-revision CI run `33156993094` passed the full retained Stable suites and the complete currently implemented Glaze UI 2.0 rendered matrix at revision `7db921e4372a851a05a4f27221493f423e641293`.

The accepted rendered matrix establishes:

- Light and Dark appearance across Mobile, Tablet, Desktop, Wide Desktop, and TV;
- Deep Dark on representative mobile and desktop surfaces;
- Clear, Balanced, and Solid material clarity;
- Calm, Balanced, and Expressive expression states;
- solid content planes with Glaze interaction surfaces;
- representative Connected Transformation continuity;
- Navigation Capsule mobile reachability, selected-state expansion, and forward-scroll compression without violating the 48px touch floor;
- Tablet rail, Desktop/Wide Desktop persistent navigation, and TV far-view navigation adaptation;
- large-text reflow without horizontal scrolling in the representative mobile case;
- reduced-motion behavior;
- reduced-transparency opaque fallback;
- forced-colors boundaries and opaque material fallback;
- no-`backdrop-filter` fallback;
- 48px general and 56px TV reference interaction floors.

The rendered gate identified and caused correction of a real reachability defect: whole-capsule forward-scroll scaling reduced nominal 48px targets to about 45px. Compression now reduces Navigation Capsule spacing/chrome instead of shrinking interaction targets.

## Dependency, privacy, and security boundary

The Candidate implementation remains dependency-free at runtime and self-contained in the repository. `scripts/validate_glaze_2_candidate.py` now fails closed on:

- browser network APIs used by the Candidate runtime;
- browser storage/cookie/cache APIs;
- common analytics/telemetry SDK markers;
- unsafe dynamic-code and HTML-write primitives;
- remote HTTP(S), protocol-relative, CDN, and CSS import dependencies in Candidate CSS/runtime/reference artifacts;
- drift away from the repository-local Candidate CSS and JavaScript imports used by the rendered reference.

These checks establish the design-system Candidate's dependency/privacy/security boundary; they do not replace application-specific security or privacy acceptance for downstream consumers.

## Explicitly not yet accepted

This record does **not** establish Stable promotion or downstream application conformance. Promotion remains blocked pending applicable evidence for:

- rendered increased-contrast (`prefers-contrast: more`) behavior beyond source-level fallback presence;
- explicit Connected Transformation fallback acceptance when View Transitions are unavailable;
- representative foldable/hinge-aware layouts;
- wearable/spatial implementation acceptance before either becomes a Stable production target;
- reconciliation of stale Stable consumer-registry evidence where current repository state has moved beyond the recorded revision;
- exact final Candidate CI evidence after all remaining acceptance changes are frozen;
- formal Stable promotion and version-state synchronization.

## Authority boundary

Glaze UI 2.0 governs presentation and interaction. Its intelligence, Live Surface, security, privacy, resilience, and Mesh presentation patterns do not create underlying execution authority, evidence, or domain truth. Wardveil Security, Privacy Shield, Everkeep, GoreeCloud Mesh, and application logic remain authoritative for their respective substantive state.

## Consumer boundary

The 2.0 design contract is the enforced active-development migration target. Glaze UI 1.6.0 remains the last validated Stable implementation baseline until 2.0 promotion. A consumer adopting 2.0 Candidate behavior is not production-eligible on that basis and must complete normal application-specific acceptance after the design-system release is promoted.
