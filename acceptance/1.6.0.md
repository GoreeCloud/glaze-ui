# Glaze UI 1.6.0 Stable Acceptance Record

## Release identity

- Stable version: `1.6.0`
- Previous Stable baseline: `1.5.0`
- Scope: retained 1.5 Stable foundation plus Evidence Presentation and Authority Surfaces and Adaptive Workspace and Navigation.
- Excluded from promotion: Glaze Motion remains Experimental; smartwatch/wearable production support remains deferred and production-blocked.

## Candidate evidence

The exact validated Candidate hardening head was `9a632e8df5ddd3a66c19ef2bb90efb7e65678048`. It passed Glaze UI CI #460, Icon Construction #145, Icon Identity #137, and Semantic Color #180, including both 1.6 browser-rendered matrices. That work was squash-merged to `main` as `cc50ad8debce49b254da424399768741b0a5a96e` before release-state conversion.

The evidence matrix caught a real Mobile 200% text-reflow overflow before promotion. The implementation was corrected and the unchanged fail-closed test passed on the final Candidate head.

## Cross-contract acceptance boundary

The Adaptive Workspace rendered matrix does not substitute for Evidence Presentation acceptance, and the Evidence Presentation rendered matrix does not substitute for Adaptive Workspace acceptance. Stable 1.6 requires both promoted systems to pass their own source, accessibility/resilience, authority, form-factor, and rendered gates together with the retained Stable regression stack on the exact final release head.

The historical Candidate-named reference pages, CSS selectors, token paths, and rendered validators are retained as immutable promotion evidence and Stable regression harnesses. Their historical names do not change the promoted lifecycle state.

## Promotion conversion

The release-state conversion changes the canonical version, lifecycle metadata, current-Stable consumer requirement, governance documents, Design Center release identity, and Stable regression labels without weakening semantic, accessibility, rendering, authority, or subsystem validation. The final promotion PR head must pass the complete exact-head workflow stack before merge.

## Authority boundaries

Glaze UI governs presentation and interaction. Privacy Shield, Wardveil Security, Everkeep, GoreeCloud Mesh, and application logic remain authoritative for their respective underlying truth. Freshness and transport availability do not become positive domain truth through Glaze UI presentation.

## Consumer effect

Promotion makes `1.6.0` the mandatory current Stable target. Existing consumers with 1.5.0 or older evidence are `migration-required` until they complete controlled 1.6 adoption and application-specific rendered/native/accessibility acceptance. Design-system promotion does not certify downstream application readiness.

## Rollback

Before merge, rollback is branch/PR-level. After merge, rollback uses a documented revert or successor patch while preserving 1.5.0, Candidate 1.6, and 1.6.0 release evidence for audit and controlled migration.
