# GLAZE UI V1.1 — Stable Acceptance Boundary

**Product:** GLAZE UI V1.1  
**Machine version:** 1.1.0  
**Current candidate state:** Release Candidate  
**Stable accepted:** No

This file defines the promotion boundary for GLAZE UI V1.1. It does not itself establish Stable status.

## Required before Stable promotion

The exact release implementation must satisfy all applicable requirements below without bypass, inherited evidence, or unreviewed release-critical changes:

1. `VERSION` and lifecycle metadata consistently identify the intended 1.1.0 candidate/release state.
2. The V1.1 release contract, web entrypoint, runtime entrypoint, optical layer, performance budget, visual-regression contract, and required repository documentation are present and internally consistent.
3. The current V1-series validator passes on the exact candidate revision.
4. The Design Center builds from the V1.1 entrypoint and passes responsive source validation.
5. Rendered Mobile UI acceptance passes at 320, 345, 390, and 412 CSS pixels with touch metrics, no horizontal overflow, required target floors, readable one-column phone composition, and reviewable light/dark screenshots.
6. The visual-regression contract contains non-empty required cases and is pinned to the reviewed exact implementation revision before promotion.
7. Semantic state colors remain separate from Deep Teal / Soft Amber atmosphere.
8. Reduced Transparency, Reduced Motion, Increased Contrast, Forced Colors, and constrained-performance fallbacks preserve hierarchy, focus, meaning, and readable interaction boundaries.
9. The numeric performance budget is enforceable and the V1.1 source remains within its declared blur, Aura, motion, and material-count limits.
10. The V1.1 runtime passes syntax validation and introduces no network or telemetry behavior.
11. The applicable native reference and form-factor validation is current for the release revision or is explicitly resolved by a governed non-applicability determination. A stale `revalidation-required` native state blocks Stable.
12. Required documentation and append-oriented change records are synchronized to the exact release state.
13. The final promotion revision receives its own exact-revision CI/release validation. Passing a predecessor revision is not sufficient if release-relevant source changed.

## Downstream boundary

Stable Glaze UI establishes the design-system release. It does not automatically make any downstream application production-ready or consumer-conformant. Each consumer remains independently acceptance-gated and must provide repository-local adoption evidence for the required Stable version.
